## 1. Objetivo y Alcance

Validar la edición de especies existentes en el catálogo productivo bajo las especificaciones de **RF-15 v1.1**, evaluando la persistencia de datos, actualización automática de timestamps, conservación del campo `grupo_manejo`, y el comportamiento ante intentos de asignación de valores fuera del conjunto admisible tanto en UI como en API.

### Sub-casos de Prueba
1. **G03-v2.0-1**: Editar nombre y descripción de una especie existente activa con datos válidos. Verificar la actualización automática del timestamp de modificación (`fecha_actualizacion` o `fecha_actualizacion_especie`) y comprobar que `grupo_manejo` permanece **sin cambios** verificado vía API desde Cypress (`GET /configuracion/especies?solo_activas=false`).
2. **G03-v2.0-2**: Verificar ausencia del control `grupo_manejo` en el formulario de edición de la interfaz de usuario (UI), y evaluar el contrato API mediante Newman enviando un valor fuera del conjunto admisible (`REPTILES`), verificando la conservación del valor anterior en base de datos.

> [!NOTE]
> **Nota sobre el Contrato HTTP para rechazo**:
> La especificación de RF-15 v1.1 **NO define** el código HTTP normativo para rechazo de "grupo_manejo fuera del conjunto admisible". El usuario y QA proponen `400 Bad Request`. El script de Newman registra contractualmente el esperado `"400 (propuesto, no normativo)"` y captura el obtenido real sin reescribir ni forzar la especificación. Si el backend responde 200 o 422, se registrará FALLA con el código y body literales para su clasificación como discrepancia/requerimiento no implementado.

## 2. Reglas Duras de Selección de Datos y Preflight

Para evitar colisiones con datos residuales, fallos de concurrencia o modificaciones sobre datos sensibles de negocio, la especie objetivo debe cumplir:
1. **NO puede ser** `F-04` / `"Ovino QA2"` ni ningún derivado que contenga `"ovino"`.
2. **Debe estar ACTIVA** (`es_activo === true` o `activo === true`).
3. Su nombre actual **NO debe contener dígitos** (la UI rechaza números bajo regex `/^[a-zA-ZáéíóúñÁÉÍÓÚÑ\s]+$/`).
4. Su nombre actual **NO debe contener** los sufijos `"Editado"`, `" Qa"` o `" Qa2"`.
5. **Timestamp NO nulo**: Debe tener `fecha_actualizacion != null` (detección dinámica de `fecha_actualizacion` o `fecha_actualizacion_especie`) para evitar el bloqueo por concurrencia HTTP 412 documentado en diagnósticos previos.
6. El nombre nuevo asignado será `"<nombre original> Editado"`. Se evalúa de forma case-insensitive ante la normalización del backend (Title Case) y se guarda el valor literal en el checkpoint.
7. **Preflight de Solo Lectura**: Se ejecuta `GET /configuracion/especies?solo_activas=false` con el token capturado del login UI. Si no se localiza ninguna candidata admisible que cumpla **TODAS** las reglas duras, la suite aborta inmediatamente sin escribir resultados incompletos ni modificar registros en la BD.
8. La especie seleccionada es la **MISMA** para Cypress y para Newman (es edición sobre especie existente).

## 3. Matriz de Checkpoints (CP-xx y NW-xx)

La suite evalúa exactamente 7 checkpoints de Cypress (`CP-01` a `CP-07`) y 4 checkpoints de Newman (`NW-01` a `NW-04`).

| ID | Herramienta | Paso | Resultado Esperado | Método de Verificación |
| :--- | :--- | :--- | :--- | :--- |
| **CP-01** | Cypress | Login UI Admin | Inicio de sesión exitoso como Administrador y redirección a `/dashboard` | `cy.loginUI`, esperar `@postLogin` 200, verificar `/dashboard`. |
| **CP-02** | Cypress | Navegación a Configuración | Navegación a `/configuracion` respetando el estado de permisos del sidebar | Esperar selector `a[href="/configuracion"]:not(.ds-sidebar__item--locked)`. |
| **CP-03** | Cypress | Apertura Modal Edición | Apertura del modal con nombre y descripción precargados | Localizar fila en tabla UI, clic en Editar, verificar valores de inputs. |
| **CP-04** | Cypress | Envío Edición Válida | Envío de formulario con datos válidos produce PATCH HTTP 200 | Interceptar `PATCH /configuracion/especies/:id` y validar status 200 exacto. |
| **CP-05** | Cypress | Avance `fecha_actualizacion` | El timestamp de actualización avanza respecto al valor previo | Comparar `fecha_actualizacion` (o `fecha_actualizacion_especie`) antes y después del PATCH. |
| **CP-06** | Cypress | Conservación `grupo_manejo` | `grupo_manejo` permanece sin cambios verificado vía API | `cy.request GET /configuracion/especies?solo_activas=false` con token capturado. |
| **CP-07** | Cypress | Evaluación control UI `grupo_manejo` | 400 (propuesto, no normativo) | Formulario UI carece de control `grupo_manejo`. Se declara FALLA con obtenido literal: `"control grupo_manejo ausente en formulario de edición"`. |
| **NW-01** | Newman | Login API Admin | Login exitoso (HTTP 200) y token Bearer presente | `POST /sesiones/` con variables `admin_email` y `admin_password`. |
| **NW-02** | Newman | Localización Especie API | Localización exacta de la misma especie candidata activa | `GET /configuracion/especies?solo_activas=false` y extracción de `target_especie_id`. |
| **NW-03** | Newman | Contrato PATCH `REPTILES` | 400 (propuesto, no normativo) | `PATCH /configuracion/especies/:id` con body `{ "grupo_manejo": "REPTILES" }`. Registra código y body literales. |
| **NW-04** | Newman | Conservación post-rechazo API | GET listado confirma que `grupo_manejo` conserva su valor previo | `GET /configuracion/especies?solo_activas=false` verificando que no mutó a `REPTILES`. |

## 4. Teardown y Gestión de Variables

- **Captura en Preflight**: En Cypress se registran en closure: `id_especie`, `nombreOriginal`, `descripcionOriginal`, `grupoManejoOriginal`, `fechaActualizacionPrevia`, `nombreNuevo`.
- **Reversión Garantizada (`after()`)**: El hook `after()` de Cypress se ejecuta **SIEMPRE** (incluso si fallan los `it()`). Revierte `nombre` y `descripcion` a sus valores originales mediante `cy.request` con el token capturado. No revierte `fecha_actualizacion` (no es reversible) y anota los metadatos en `evidencias/teardown_cypress.json`.
- **Newman Protegido**: Las variables (`target_especie_id`, etc.) se asignan al **inicio** de los scripts de test en Postman antes de cualquier aserción.
